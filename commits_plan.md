# Plan de Control de Versiones (Commits)

Este documento contiene el plan de subida al repositorio de GitHub para simular el desarrollo progresivo del portafolio. Está dividido en 3 días, con 5 commits por día (cada 30 minutos).

## 📅 Día 1: Configuración y Base (HOY)
1. `init: inicializar estructura del proyecto y archivos base`
   - *Se subirá la estructura principal.*
2. `feat: agregar esqueleto HTML semántico y metaetiquetas`
   - *Commit estructural.*
3. `style: definir variables globales CSS (Design Tokens) y reset`
   - *Se agregará la hoja de estilos base.*
4. `feat: construir barra de navegación responsive y menú hamburguesa`
   - *Commit de interactividad y maquetación.*
5. `feat: implementar sección de Inicio (Hero) y presentación`
   - *Se agregarán las imágenes (carpeta media).*

## 📅 Día 2: Maquetación de Secciones (MAÑANA)
6. `feat: maquetar sección Sobre Mí y línea de tiempo de educación`
7. `feat: integrar sección de Habilidades con iconos de Devicon`
8. `feat: estructurar grilla de Proyectos Destacados`
9. `feat: diseñar formulario de Contacto y pie de página`
10. `docs: crear página de documentación del Design System`
    - *Se subirá el archivo design-system.html.*

## 📅 Día 3: Interactividad y Responsive (PASADO MAÑANA)
11. `style: aplicar Flexbox y CSS Grid a contenedores principales`
12. `style: perfeccionar diseño responsive para móviles y tablets`
13. `feat: implementar lógica de Dark/Light mode con localStorage`
    - *Se subirá el archivo main.js.*
14. `feat: agregar filtros de proyectos, validación de formulario y modales`
15. `fix: pulir animaciones de scroll, botón flotante y correcciones móviles`
    - *Se subirá el README.md final.*

---
**Instrucciones de uso para mí (Antigravity):**
Cuando me pidas subir versiones, leeré este archivo y crearé los commits correspondientes. Para las versiones estructurales usaré el comando `--allow-empty` o fraccionaré los archivos, de modo que el historial quede perfecto.
